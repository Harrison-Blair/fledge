# FTHR-021: Migrate this repo's specs to .fledge/pluma/, bump to 0.4.0, and refresh the dogfood scaffold

## Description
Closeout feather for PLM-011: bump `VERSION`/`binaryVersion` from 0.3.4 to 0.4.0 (this is a breaking convention change, matching the repo's practice of bumping on breaking changes — see FTHR-013), physically move this repo's own spec files from `pluma/` to `.fledge/pluma/` (`git mv`), rebuild and reinstall the binary, then run `fledge init --refresh` once so the repo's own `.fledge/scaffold.json` and mirrored `.fledge/skills/` copy are regenerated consistently against the new code (FTHR-017), the new embedded prose (FTHR-018), and the fixed txtar suite (FTHR-020). One rebuild/reinstall/refresh cycle covers both the version bump and the migration.

## Affected Modules
Per `.fledge/nest/entry-points.md` and FTHR-013's precedent (PLM-009):
- `VERSION` (root) — `0.3.4` → `0.4.0`.
- `internal/cli/version.go` — `binaryVersion` var → `"0.4.0"` (pinned to `VERSION` by `version_test.go:TestBinaryVersionMatchesVersionFile`; both must move together).
- Repo root — `git mv pluma .fledge/pluma` (moves `pluma/plumage/PLM-001..011` and `pluma/feathers/FTHR-001..021`, i.e. all existing spec files, preserving git history via rename detection).
- `.fledge/scaffold.json` — regenerated by `fledge init --refresh` (new stamp entries for `.fledge/pluma/plumage/.gitkeep`, `.fledge/pluma/feathers/.gitkeep`; obsolete `pluma/*.gitkeep` stamp entries pruned per `internal/bootstrap/drift.go:PruneObsolete` — note only `.gitkeep` placeholders are stamped, not the real spec files, so the real specs are unaffected by prune and must be moved by the explicit `git mv` above, not by refresh).
- `.fledge/skills/` — resynced from `internal/bootstrap/core/` (FTHR-018's corrected prose) by the same refresh.

## Approach
1. Bump `VERSION` to `0.4.0` and `internal/cli/version.go`'s `binaryVersion` to `"0.4.0"` together.
2. `go install ./cmd/fledge && hash -r`; confirm `fledge version` reports `0.4.0`.
3. `git mv pluma .fledge/pluma` — moves both `pluma/plumage/` and `pluma/feathers/` subtrees intact.
4. Run `fledge init --refresh` at repo root — expect it to regenerate `.fledge/scaffold.json` (new `.gitkeep` stamp paths, obsolete old ones pruned) and resync `.fledge/skills/` from the FTHR-018-corrected embedded prose. Review the refresh report: no unexpected prunes of user content, no "kept (user-edited)" surprises.
5. Verify: `fledge preen` (scaffold healthy, no validation errors on the moved specs), `fledge status`, `fledge vee`, `fledge ready`, `fledge unfledged` (all specs visible and correctly resolved at the new location, including this plumage's own feathers).
6. Full `go build ./...` and `go test ./...` (including the now-fixed `cmd/fledge` txtar suite from FTHR-020) green at 0.4.0.

## Tests
- `internal/cli/version_test.go` (`TestBinaryVersionMatchesVersionFile`) — already exists; observed FAILING if only one of `VERSION`/`binaryVersion` is bumped (capture that as the pre-fix evidence: bump only `VERSION` first, run the test, see it fail, then bump `binaryVersion` too and see it pass), then passing once both match.
- Manual/scripted verification recorded in the evidence file: `fledge version` output (0.4.0), the `git mv` diff (rename-detected, no content changes), the `fledge init --refresh` report (stamp updated, prose resynced, no unexpected prunes), and `fledge preen`/`status`/`vee`/`ready`/`unfledged` output confirming all specs resolve correctly post-move — pins FC-3.
- Full `go test ./...` — pins AC-1 of the parent plumage.
