# FTHR-030: Regenerate dogfood scaffold to add update allow-list entry

## Description
Closeout for PLM-015 in this dogfooded repo: regenerate the fledge-owned scaffold with the
`update`-inclusive binary so this repo's own generated allow-list
(`.claude/settings.local.json`) gains `Bash(fledge update *)`. The scaffold version stamp
(`.fledge/scaffold.json`) is already current (`0.5.4`), so the operative change is the added
allow-list entry; the stamp is left as `fledge init --refresh` writes it (idempotent).

Depends on FTHR-028: the regenerated allow-list only contains `update` once the installed
binary's `commandOrder` includes it.

Satisfies PLM-015 FC-4 (this repo's allow-list carries `update`).

## Affected Modules
- `.claude/settings.local.json` — this repo's generated Claude allow-list (regenerated by
  `fledge init --refresh`); gains the `Bash(fledge update *)` entry (currently absent —
  `grep -c 'fledge update' .claude/settings.local.json` returns 0).
- `.fledge/scaffold.json` — the scaffold stamp; rewritten by `--refresh` but its
  `fledgeVersion` is already `0.5.4`, so no version change is expected. See
  `.fledge/nest/architecture.md` (stamp/drift) and `.fledge/nest/conventions.md` (scaffold
  write policies).

## Approach
1. Ensure FTHR-028 is merged to main and reinstall the binary from that source
   (`go install ./cmd/fledge`; `hash -r`) so the installed `fledge` emits `update` in the
   generated allow-list. Confirm with `fledge version` (matches `VERSION`).
2. Capture the **before** state as evidence: `grep -c 'fledge update'
   .claude/settings.local.json` returns 0 (no pre-approval entry for the shipped command).
3. Run `fledge init --refresh` in the repo (it resets fledge-owned files to the shipped
   versions and rewrites `.fledge/scaffold.json`). Review `git status` — the expected diff
   is the added `Bash(fledge update *)` allow-list entry; the stamp and other fledge-owned
   content should be unchanged (already current). If `--refresh` reports other user-edited
   files, stop and surface them rather than force-overwriting.
4. Capture the **after** state: `.claude/settings.local.json` now contains
   `Bash(fledge update *)`, and no `fledge` command prints a stamp-mismatch warning (it does
   not today either — the stamp is already current; assert its continued absence).
5. Commit the regenerated `.claude/settings.local.json` (and `.fledge/scaffold.json` if
   `--refresh` touched it).

Constraints: this is a regeneration via the CLI, not a hand-edit — never hand-modify the
allow-list or stamp. Do not use `--force` unless `--refresh` refuses on a genuinely expected
overwrite you have reviewed; if it flags unexpected user edits, surface them.
