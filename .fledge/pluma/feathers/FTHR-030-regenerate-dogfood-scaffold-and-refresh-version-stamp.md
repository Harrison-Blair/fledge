# FTHR-030: Regenerate dogfood scaffold and refresh version stamp

## Description
Closeout for PLM-015 in this dogfooded repo: regenerate the fledge-owned scaffold with the
`update`-inclusive binary so this repo's own generated allow-list gains `Bash(fledge
update *)`, and refresh the stale `.fledge/scaffold.json` stamp (currently `0.4.0`) to the
current binary version so no `fledge` command in this repo prints a stamp-mismatch warning.

Depends on FTHR-028: the regenerated allow-list only contains `update` once the installed
binary's `commandOrder` includes it.

Satisfies PLM-015 FC-2 (this repo's allow-list carries `update`) and FC-4 (no stamp
warning).

## Affected Modules
- `.claude/settings.local.json` — this repo's generated Claude allow-list (regenerated by
  `fledge init --refresh`); gains the `Bash(fledge update *)` entry.
- `.fledge/scaffold.json` — the scaffold stamp; `fledgeVersion` moves from `0.4.0` to the
  current binary version. See `.fledge/nest/architecture.md` (stamp/drift) and
  `.fledge/nest/conventions.md` (scaffold write policies).

## Approach
1. Ensure FTHR-028 is merged to main and reinstall the binary from that source
   (`go install ./cmd/fledge`; `hash -r`) so the installed `fledge` emits `update` in the
   generated allow-list and reports the current `VERSION`. Confirm with `fledge version`.
2. Capture the **before** state as failing evidence: run a normal command (e.g.
   `fledge preen`) and record that it prints the `scaffold was written by fledge 0.4.0 …`
   mismatch warning to stderr, and that `.claude/settings.local.json` contains no
   `fledge update` entry.
3. Run `fledge init --refresh` in the repo (it resets fledge-owned files to the shipped
   versions and rewrites `.fledge/scaffold.json` with the current `binaryVersion`). Review
   `git status` — the expected diff is the added `Bash(fledge update *)` allow-list entry
   and the bumped stamp version; nothing else fledge-owned should change (content is not
   otherwise drifted). If `--refresh` reports other user-edited files, stop and surface
   them rather than force-overwriting.
4. Capture the **after** state: `fledge preen` (and other commands) print no mismatch
   warning, and `.claude/settings.local.json` now contains `Bash(fledge update *)`.
5. Commit the regenerated `.claude/settings.local.json` and `.fledge/scaffold.json`.

Constraints: this is a regeneration via the CLI, not a hand-edit — never hand-modify the
stamp or the allow-list. Do not run with `--force` unless `--refresh` refuses on a
genuinely expected overwrite you have reviewed; if it flags unexpected user edits, surface
them.

## Tests
This feather is a dogfood regeneration; its behavior is verified by captured command
evidence rather than a new Go unit test (mirrors prior dogfood-closeout feathers). The
test-first discipline is honored via before/after capture:
- **Before (failing):** `fledge preen` prints the `0.4.0` stamp-mismatch warning; `grep -c
  'fledge update' .claude/settings.local.json` returns 0. Recorded verbatim under AC-1.
- **After (passing):** the same `fledge preen` prints no mismatch warning; the same grep
  returns ≥1. Recorded under AC-1.
- The existing suite (`go test ./...`) must remain green after the regen.
